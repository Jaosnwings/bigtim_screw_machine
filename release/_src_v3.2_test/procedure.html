鎖螺絲站 v3.2 現場點位測試程序

日期：2026-11-03　PLC v3.2（FX5S 192.168.1.21）　HMI v5（ET-6400WA 192.168.1.100）　測試人員：__________
今天只做點位與元件之間的溝通確認，不追求自動流程跑完。任何一步看不到預期反應，就在紀錄表寫下「看到什麼」，然後繼續下一項，不要自己改程式。
人員安全：手不要伸進治具與鎖付頭下方。要測治具會動的項目前，先喊一聲、確認旁邊沒人。急停（EMO）隨時可以按。

0. 準備（約 30 分鐘）

#動作確認完成
0-1筆電網路設 192.168.1.x（例如 .50），能 ping 到 192.168.1.21（PLC）與 192.168.1.100（HMI）。兩個都通
0-2先備份：GX Works3 → Online → Read from PLC，讀回後另存成 PLC_backup_20261103.gx3。檔案已存
0-3開 PLC\ScrewMachine_v3_2.gx3 → Online → Write to PLC（全部）。CPU 不允許遠端重置，寫完要關電再開一次。PLC RUN 燈亮、ERR 燈不亮
0-4開 GP-Pro EX 5.02，HMI\ScrewMachine_HMI_v5_PLCv3_2.prxe → Transfer Project → 傳到 192.168.1.100。連線密碼問主管（不寫在文件裡）。HMI 開機後看得到手動頁、IO 監視頁
0-5開 IO 側錄（見第 3 節），整個測試期間都開著。每做一大項就停掉重開一次，用 --tag 標項目，例如 --tag A3_EMO。畫面每 2 秒有「讀 n 次」在增加
v3.2 上電預設：停止、手動模式關、Local（不連中控）。急停一上電如果是按著的，Y3（治具停止）會一直 ON，要先放開急停再按「復歸流程」。

1. 主要任務 A：治具點位、EMO、啟動流程

A1　治具與按鈕的輸入點（HMI：手動頁 → IO 監視／強制）

#操作預期（IO 監視頁）OK/NG
A1-1不動任何東西，抄下目前亮的 X 點正常應亮：X0、X5、X10、X11、X12（X4 一直亮是已知）
A1-2按下 EMO，再放開X0 按下熄、放開亮（ON＝正常）
A1-3按 HMI 箱 EMO 旁的綠色啟動鍵，按住 2 秒再放X7 跟著亮、熄。另外記：X1 有沒有一起亮
A1-4手遮光柵，再移開X10 遮住熄、移開亮
A1-5治具在水平待命位置 / 離開水平（請治具工程協助）X5 在水平時亮
A1-6讓治具送「停止／異常」（請治具工程協助）X6 亮

A2　PLC 送給治具的輸出點（手動模式）

手動頁按「自動／手動切換」→ 狀態列「手動模式」燈亮。

#操作預期OK/NG
A2-1手動頁「治具停止 Y3」按一下Y3 小燈亮，治具停住／不能動（治具工程確認收到）
A2-2再按一次「治具停止 Y3」解除，開始用手錶計時治具自己回水平 → X5 亮。記秒數：____ 秒（30 秒內）
A2-3「治具啟動 Y5」按一下（0.5 秒脈衝）治具前進一站（移到鎖付點 01）。記：治具有沒有動、動到哪
A2-4再按一次「治具啟動 Y5」治具移到鎖付點 02
A2-5再按一次「治具啟動 Y5」治具回水平？記實際行為（這題現場還沒確認）
A2-6IO 監視頁看 Y4（安全位置）Y4 跟著 X12（RC75 原點）同時亮。Y4 不能強制是正常的
A2-7IO 監視頁：Y0 紅燈、Y1 綠燈、Y2 蜂鳴器各按「強制」一下，看完再按一下解除塔燈紅、綠、蜂鳴器各自動作。記：哪一顆實際亮
「治具啟動 Y5」需要 X12（原點）與 X10（光柵）都亮才會送出。按了沒反應，先看這兩顆燈。

A3　EMO（急停）

#操作預期OK/NG
A3-1按下 EMO立刻：Y3 ON（治具停）、Y0 紅燈、Y2 蜂鳴器響、強制全部解除
A3-2放開 EMO，等 10 秒什麼都不能自己動；Y3 仍然 ON
A3-3手動頁「復歸流程」按一下，開始計時順序：RC75 RESET（Y11）→ Z 軸回原點（X12 亮）→ Y3 解除 → 治具回水平（X5 亮）→ 紅燈、蜂鳴器停。記總秒數：____ 秒
A3-4治具在動的時候（A2-3 期間）按 EMO治具立刻停（看治具工程端）

A4　啟動流程（一次按鈕，治具走兩點）

可以空打（拿掉螺絲），重點是看 PLC 與治具、RC75 的交握順序。這一項要開側錄（--tag A4_START）。

#操作預期OK/NG
A4-1回自動頁：手動頁再按一次「自動／手動切換」（手動模式燈熄）→ 回自動頁面確認狀態列：X0、X10、X11、X12、X5 亮，X13、X6 不亮
A4-2自動頁按「啟動」綠燈（Y1）開始閃 = 等啟動鍵
A4-3按 HMI 箱綠色啟動鍵（X7）一次Y5 送出 → 治具移到點 01 → 約 3 秒後 Y12 → RC75 鎖第 1 點 → X12 熄再亮、X14 亮
A4-4不用按，等PLC 自動再送 Y5 → 治具移到點 02 → 鎖第 2 點 → 再送 Y5 → 治具回水平（X5）→ 綠燈回到閃
A4-5停在哪裡就記哪裡寫下最後看到的燈、治具位置、HMI 訊息
目前治具沒有「到位」訊號給 PLC，程式是 Y5 送出後固定等 3 秒就開始鎖。治具 3 秒內沒到位就會鎖空 — 這次要記下治具實際要幾秒才到位。

2. 任務 B：RC75 基本點位

#操作（手動模式）預期OK/NG
B-1靜止時看 IO 監視頁X11 READY 亮、X12 原點亮、X13 ALARM 不亮、Y14 TABLE 1 一直亮
B-2手動頁「RC75 RESET」按住 1 秒Y11 亮；RC75 面板異常清除
B-3手動頁「送螺絲」按住 1 秒Y13 亮，送料器動作
B-4手動頁「單次鎖付」按一下（--tag B4_SINGLE）Y12 0.5 秒 → X12 熄（Z 下降）→ X14 循環完成亮 → X12 再亮。X17（締付 OK）有沒有亮？
B-5拿掉螺絲再「單次鎖付」一次（空打）這次 X17 應該不亮。如果還是亮，X17 可能接到 CHUCK TIP
B-6Z 不在原點時按「RC75 RETURN」按住Y10 亮，Z 回原點後 X12 亮
B-7螺絲用完或讓 RC75 報異常（可做就做）螺絲不足 X15 亮；異常 X13 亮；X16 蜂鳴

3. CSV 側錄（每一大項都要交）

  1. 筆電要裝 Python 3.8 以上（只用內建函式庫）。
  2. 雙擊 tools\io_rec.bat，或在 tools 資料夾開命令列：
    python io_rec.py --tag A4_START
  3. 開始後畫面每 2 秒會顯示「讀 n 次、寫 n 列、最後變化」。做完這一項按 Ctrl+C 停止。
  4. CSV 存在 tools\csv\io_rec_日期時間_標籤.csv，Excel 可直接開。每一列是一次變化：時間（毫秒）、哪個點變了（例如 X7↑ Y5↑）、全部 X/Y 的 0/1、步序 D100、第幾點 D222。
  5. 注意：PLC 只有一個 Modbus 連線，側錄時不要開其他 Modbus 工具（例如 io_grid）。GX Works3 監看與 HMI 不受影響。
  6. 收工時把整個 tools\csv 資料夾連同測試紀錄表一起交回。

4. 異常時怎麼辦

狀況處理
任何危險、治具亂動按 EMO。之後照 A3-3 按「復歸流程」。
HMI 上的強制按鈕沒反應確認是手動模式、停止中、EMO 放開；強制 30 秒（按住型 3 秒）會自動解除，是正常的。
HMI 與 PLC 斷線強制會在 2 秒內自動解除。檢查網路線、HMI 畫面右上角。
測試做不下去，要還原舊程式GX Works3 開 0-2 備份的 PLC_backup_20261103.gx3 → Write to PLC → 關電再開。HMI 傳回 v4（ScrewMachine_HMI_v4_ET6400WA.prxe）。
GX Works3 有用過「強制 I/O（Forced Input/Output）」收工前 Debug → Register/Cancel Forced Input/Output → Cancel All Registrations。這個強制表 PLC 自己解不掉，急停也不會解除。
