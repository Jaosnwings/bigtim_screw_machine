1. 設計原則與範圍

  • 只換資料進出方式，不改流程。PLC 的自動步序、HMI、V10 交握語意（開始／放行／ACK／完工）全部不變。原本中控用 Modbus 寫進 D7000～D7029 的內容，改成整包放在 HO 訊框；原本中控用 Modbus 讀的 D7100～D7151，改成整包放在 ST 訊框。
  • 狀態同步，不逐筆確認。HO 與 ST 都是「目前狀態快照」，每 1 秒送一次，內容有變化時立刻再送。掉一筆沒關係，下一筆會補上，所以沒有 ACK、沒有重送、沒有序號。
  • 條碼機（八扣／barcode）整合進 PLC。SICK Lector 改由 PLC 連線與觸發。中控要讀碼時送 TG，PLC 觸發 SICK、取回條碼後用 SC 回覆。中控不再直接連條碼機（同一台條碼機只能有一個主人）。
  • 混合版、可切換。PLC 參數 D236：0 = Modbus（舊版行為，完全不變）、1 = socket。中控 targets.json 每站 transport：modbus / socket。兩邊要同時切。

2. 系統架構與連線

項目規定
角色中控 = TCP server，PLC = TCP client（Active open）。PLC 一開機（D236=1 且停止中）就主動連線，斷了自己重連。
位址中控 192.168.1.200 埠 9500（PLC 參數 D243～D246、D247 可改）。
站的辨識連上後 PLC 的第一筆必須是 HI，中控用 st（站號）與 eq（設備編號）綁定。eq 與中控登錄不符（站 2 = MC-D002）或 5 秒內沒收到 HI，中控直接關線。
連線數中控每站只保留一條連線；同一站再連進來，舊的那條會被關掉。
條碼機PLC 另開兩條 client 連線到 SICK（2111 觸發、2112 資料）。若連線數不夠，可設成同一埠（見 §6）。

3. 訊框通用規則與拆解方法

項目規定
字元ASCII，只用可列印字元 0x20～0x7E。
結尾每筆以 CR LF（0x0D 0x0A）結尾。接收端看到 LF 就是一筆結束，LF 前面若是 CR 就去掉。
格式型別;key=value;key=value…。型別 2 個大寫字母。
固定長度欄位順序固定、每個 value 長度固定。數字左補 0，字串右補空白，16 進位用大寫。所以每種訊框總長固定，PLC 可以直接用位置取值，不必找分號。
字串內容字串欄不得含 ; =（送出前換成空白）。
最大長度一行超過 120 字元（PLC 端）／512 位元組（中控端）整行丟掉。
未知型別整筆丟掉、錯誤計數 +1，不斷線。

3.1 TCP 是位元組串流：一定要自己組行

TCP 不保留「一筆」的邊界：一次收到的資料可能只有半筆、剛好一筆、或好幾筆黏在一起。PLC 必須準備一個行緩衝，每收到資料就逐位元組處理：

3.2 位元組 ↔ 字元件（FX5 的放法）

FX5 的 SP.SOCRCV / SP.SOCSND：緩衝第 0 字 = 位元組數，之後每個字放 2 個位元組，先到的位元組放低位元組。奇數長度時最後一個字的高位元組無效。

字串寫進 D7003～D7023 時的位元組順序（給 HMI 顯示用）：每個字放 2 個字元，沿用現有參數 M2091：OFF = 第 1 字元放高位元組（中控預設 High-Byte First），ON = 放低位元組。這跟 SOCRCV 緩衝的放法無關，要分開處理。

5. 交握流程

下圖是一件產品從連線到出站的完整順序。粗體位元都是 V10 原本就有的交握位元，語意與 Modbus 版完全相同，只是改由 HO（b、code）與 ST（sw）攜帶。

5.1 交握規則重點（PLC 必須照做）

規則內容
心跳中控 hb 每秒 +1。PLC：D7000 有變化就算連線正常；D216（預設 5.0 秒）沒變化 = 中控通訊中斷 M2052，自動降 Local。ST 的 hb 一律照回最後收到的值。
Remote / LocalHMI 選 Remote（M2050）且 B00=1 且心跳正常才是 Remote（B08=1）。只在停止或待機時切換；加工中斷線做完這一件。
開始B01 開始 保持到看到 B04 ACK開始。
放行B01 防呆放行 在通訊中斷時不算數；用過一次後，要中控清回 0 才可再用。
完工B02 完工 + B09 Result_Ready 保持到 B05 ACK完工；收到後兩者一起清。
立刻送 STD7107（sw）或 D7105（run）一變化就送，不等 1 秒，讓中控不漏掉短暫的邊緣。
不准用 Modbus 寫D236=1 時，D7000～D7029 只能由 HO 寫入；中控不可再用 Modbus 寫這一站（Modbus 讀可以）。

6. 條碼機（SICK Lector）由 PLC 控制

項目規定
觸發方式 D2480（預設）= CoLa-A：觸發埠送 <STX>sMN mTCgateon<ETX> 開始讀，讀完或逾時送 <STX>sMN mTCgateoff<ETX>（站 8 Lector611 實測可用）。
1 = 在資料埠送 1 個位元組 STX（0x02），與舊中控 ScannerAdapter 的作法相同。
連線觸發埠 D241（預設 2111）、資料埠 D242（預設 2112），IP D237～D240（預設 192.168.1.25）。D241 = D242 時只用一條連線（觸發與收條碼都走連線 3），連線數不夠時用這個。
觸發埠的回覆CoLa 回覆（如 sAN mTCgateon 1）讀出來丟掉即可，否則接收緩衝會塞滿。
條碼內容只取 STX 與 ETX 之間；若 SICK 設定沒有 STX，第一個可見字元就開始收，碰到 ETX/CR/LF 結束。最多 32 字，多的丟掉。
時間PLC 讀取逾時 D249 = 3.0 秒；中控等 SC 4 秒。PLC 一定要在中控放棄之前回覆。
一次一筆讀取中再收到 TG 一律忽略（不回）。中控逾時後自己重送新的 rid。

7. 連線狀態機、逾時與錯誤處理

狀況PLC 行為中控行為
5 秒沒收到 HO關線、3 秒後重連；心跳逾時 → 中控通訊中斷 M2052、降 Local—
5 秒沒收到 ST—判站離線（讀取失敗），等 PLC 重連
格式錯（長度、分隔字、字元）整筆丟、D7162 +1，不斷線、不動 D7000～D7029整筆丟、計數 +1，不斷線
第一筆不是 HI / eq 不符—（會被關線，等 3 秒重連）關線
半筆資料時斷線行緩衝清空同左
完工待收時斷線B02/B09 與結果資料保留，紅燈；重連後 ST 繼續帶 B02=1重連後照常收、回 ACK完工
SICK 連不上TG 直接回 NoRead；每 3 秒重連收到 NoRead

8. PLC 端實作規格（FX5，參考實作 v3.14）

8.1 指令（GX Works3 ST，FX5S 已驗證可編譯）

SP_SOCOPEN (EN, 'U0', 連線號, D2200, M2200);          (* 控制資料 10 字、完成位元 2 個 *)
SP_SOCCLOSE(EN, 'U0', 連線號, D2210, M2202);
SP_SOCSND  (EN, 'U0', 連線號, D2212, D6800, M2204);   (* D6800 = 位元組數，D6801~ 資料 *)
SP_SOCRCV  (EN, 'U0', 連線號, D2214, D3000, M2206);   (* D3000 = 位元組數，D3001~ 資料 *)
  • 第 2 個引數必須寫成字串 'U0'（含單引號），寫成 U0 會報 0x12011067。
  • EN 只給 1 個掃描的脈衝；指令每個掃描都要呼叫（EN=FALSE 時不動作）。完成位元 +0 在完成的那個掃描 ON，+1 = 異常完成，錯誤碼在控制資料 +1。
  • 開啟用控制資料指定對方，參數頁「外部設備連接設定」不要佔用連線 1～3：
控制資料值說明
+016#8000用控制資料 +2～+9 的設定開啟
+216#0200TCP、socket 通訊、Active open
+34001 / 4002 / 4003本機埠（避開 5549～5569）
+4 / +5IP 低字 / 高字192.168.1.200 → +4 = 16#01C8、+5 = 16#C0A8
+69500 / 2111 / 2112對方埠

狀態特殊暫存器：SD10680 開啟完成（bit0 = 連線 1）、SD10682 收到資料（bit0 = 連線 1）。收到資料位元 ON 且沒有接收中，就發一次 SP.SOCRCV；一次只能有一個 SOCSND 在進行中（等完成位元再送下一筆，優先順序 HI → SC → ST）。
